# DeepSeek 对话

一个在 iPhone 和电脑浏览器里都能用的网页 App：打开就能和 DeepSeek 官方 API 对话。

没有后端、没有账号体系、不上架 App Store。API Key 和聊天记录都只存在这台手机里。

---

## 三步用起来

1. **启动服务**（Mac 上）：双击 `启动手机版.command`。
2. **打开**：手机和 Mac 连同一个 Wi-Fi，Safari 访问终端里显示的地址，形如
   `http://192.168.2.149:8000`；电脑上直接用浏览器打开同一个地址即可。
3. **添加到主屏幕**：Safari 底部「分享」→「添加到主屏幕」。
   之后从桌面图标进入，就是全屏无地址栏的样子，和原生 App 几乎一样。

首次进入点「填入 API Key」，粘贴在 [DeepSeek 开放平台](https://platform.deepseek.com/api_keys) 创建的 Key，点「完成」即可开始。

## 界面（v3.5）

按 iOS 的玻璃质感做的视觉，v1.2 换成蓝色主题：

- **蓝色渐变背景**：顶部深蓝 → 中段靛蓝 → 底部近黑，叠一层蓝/青极光；浅色主题是蓝白渐变。
- **头像是自定义形象**：消息头像用 `avatar.jpg`（圆形），首页大图用 `icon-180.png`。
- **顶栏**：标题 + 模型徽标（带在线状态点），透明底，直接透出背景渐变。
- **空状态**：按时段问候（早上好 / 夜深了…），四张带图标的建议卡片。
- **消息**：用户气泡带渐变和内侧高光；助手消息保留纯文本排布，不套框，长文更好读。
- **输入框**：玻璃胶囊，聚焦时有一圈柔和光晕；发送键是渐变圆钮。
- **等待首字**：三个呼吸的圆点，替代空白等待。
- **回到底部**：长对话上翻后右下角浮出小圆钮。
- **设置**：分成「连接 / 模型 / 行为 / 外观 / 数据」五组卡片，滑杆有渐变填充。
- **报错**：红色卡片内嵌「重试」按钮，不必再翻操作条。
- **电脑上**：左侧常驻会话栏、中间 780px 聊天列、设置变成居中两栏弹窗；窗口窄于 960px 时自动回到手机布局。

## 电脑上（v3.5）

浏览器直接打开同一个地址，会自动切到桌面布局：

- **左侧会话栏常驻**：点左上角菜单可以收起，收起状态会记住。
- **聊天列居中**：内容最宽 780px，两边留白，长文更好读。
- **设置变成弹窗**：居中显示、分两栏，不用占满整个屏幕。
- **Enter 发送**：`Enter` 发送，`Shift + Enter` 换行；`⌘/Ctrl + Enter` 仍然可用。
- **粘贴 / 拖拽图片**：从截图工具或 Finder 里拖进来、直接 `⌘V` 粘贴，都会变成待发送的附件。
- **Esc 关闭**：设置、会话抽屉、大图都能用 Esc 关掉。
- **窄窗口自动降级**：窗口宽度小于 960px 时，自动回到手机布局，不会出现挤压。

## 功能

- **流式输出**：回复逐字出现，可随时点停止按钮中断。
- **两个模型**：`deepseek-flash`（V4.1-Flash，1M 上下文、支持识图）与 `deepseek-v4-pro`（推理更强、不支持图片）。
- **识图**：点输入框左侧的图片按钮选图，最多 4 张，发送前自动压缩到 1280px / JPEG。
- **思考模式**：可开关，强度分低/高/最高；开启时先推理再答，思考过程折叠显示。
- **多会话**：左上角菜单里新建、切换、删除；标题按首句自动生成。
- **星标置顶**：会话右侧点星号，标星的会话排在最前面（金色实心），其余保持原有顺序。
- **Markdown 渲染**：标题、列表、表格、引用、代码块（带一键复制）、行内代码、链接。
- **本地持久化**：对话存在 `localStorage`，关掉再开还在；可导出 / 导入 JSON 备份。
- **上下文用量**：顶栏是一整条进度条（占满宽度、带底槽），旁边标 `12.4K/1M`；60% 转黄、85% 转红，点数字看详情（含"还剩多少"）。
- **记忆范围**：精简 20 轮 / 标准 60 轮 / 长记忆（不设轮数上限，带到 800K token 为止）。
- **可调项**：角色设定、我的人设、我们的关系（三项都按对话独立）、温度、思考强度、历史轮数、深浅色外观。
- **错误提示**：401 / 402 / 429 / 5xx 都会翻译成中文说明，附上服务端原文，并给一个「重试」。
- **上下文超长自动兜底**：请求被拒时自动精简历史并重试一次。

## 角色、我的人设、我们的关系（v3.4）

**每个对话各存三份设定，互不影响**：它是谁（角色设定）、你是谁（我的人设）、你们怎么相处（我们的关系）。在 A 对话里改任何一项，B 对话都不会跟着变。

- **在哪改**：设置 → 行为 → 三个输入框，从上到下分别是「本对话的角色设定」「我的人设」「我们的关系」。
- **新建对话**：会继承当前对话的三项设定，作为一次性快照；之后两边各改各的。
- **旧数据**：升级时会把原来的全局提示词一次性复制给每个已有对话，所以升级后对话的样子不变；之后它们就各自独立了。
- **备份/导入**：三项设定都跟着对话一起存、一起导出；导入旧备份时，备份里的全局提示词会补给每个对话。
- **没有打开对话时**（比如刚清空全部），输入框变成「新对话的默认设定」，只影响之后新建的对话。

背后是对话对象上多了 `system`、`userPersona`、`relationship` 三个字段。请求时按「角色 → 我的人设 → 我们的关系 → 长期记忆」的顺序拼进 system；只有遇到没有这些字段的旧数据，才临时回落到全局默认值。

## 模型与识图

| 模型 | 上下文 | 识图 | 说明 |
| --- | --- | --- | --- |
| `deepseek-flash` | 1M | ✅ | V4.1-Flash-1017，速度与效果最均衡，默认选它 |
| `deepseek-v4-pro` | 1M | ❌ | V4-Pro-0813，复杂推理更强，价格更高 |

发图时如果当前选的是 V4 Pro，程序会自动切到 Flash 并提示，因为只有 Flash 支持图片。

识图相关的几个数字：

- 图片在发送前会被压到**最长边 1280px、JPEG 82%**，一张通常 150–400 KB。
- 官方对每张图最多收 **1024 token**（内部会缩放到约 1300×1300）。
- 一条消息最多 4 张图，避免请求体和本地存储一起爆掉。
- 图片会随对话存在 `localStorage` 里；**存满时会自动丢弃最老消息的图片**（文字保留），并提示一次。

## 上下文用量怎么算的

顶栏那枚 `12.4K/1M` 就是当前对话占用多少上下文：

- **优先用真实值**：每次回复后，从流式响应的最后一个 chunk 里取 `usage.prompt_tokens + completion_tokens`。
- **没有就估算**：接口没返回 usage（或刚删过消息）时，按字符数本地估算，中文约 0.8 token/字、英文约 0.28 token/字符，图片每张算 1000。
- **点一下徽标**会说明这个数字是「实际用量」还是「本地估算」，以及当前会话多少条消息。
- 模型上限按 **1M** 算。到 60% 变黄、85% 变红，同时下方细进度条跟着变色。

顺带把 V3 时代的 52K 预算调到了 **800K**——之前那是个为 64K 上下文设的保守上限，现在模型支持 1M，没必要卡这么死。真正限制长度的还是设置里的「携带历史」轮数（默认 20）。

## 对话保存在哪（v2.5）

**三层，从最脆弱到最可靠：**

| 层 | 位置 | 作用 | 会不会丢 |
| --- | --- | --- | --- |
| 工作副本 | 手机 Safari 的 `localStorage` | 你看到的一切都来自这里 | 会 |
| 自动备份 | 电脑 `backups/latest.json` + `backups/auto/`（保留 30 份） | 每 45 秒、切走页面时、启动 3 秒后自动写一份 | 电脑在就不会 |
| 手动导出 | 「文件」App 里的 JSON | 你自己留的底 | 不会 |

**工作副本的真实风险**（按概率排）

1. **换地址 = 换保险箱**。浏览器的存储按"来源"隔离，`192.168.2.149` 和 `192.168.2.150` 是两个不同的网站。路由器重新分配 IP，你就会看到"对话全没了"——其实还在旧地址名下，取不回来。
2. **iOS 的"清除历史记录与网站数据"** 会连 localStorage 一起清掉。
3. **7 天不用可能被系统回收**（加进主屏幕的网页应用通常豁免，但不保证）。
4. **5MB 上限**。图片多了会满，程序会在满时丢弃最老消息里的图片（文字保留）。
5. 手机丢失、换机、系统重置。

**自动备份怎么工作（v2.6 加固）**

| 措施 | 说明 |
| --- | --- |
| 触发时机 | 每次回复后 5 秒推一次；切走页面时用 `sendBeacon` 再推；启动 3 秒后推 |
| 原子写入 | 先写临时文件 → `fsync` 落盘 → `rename`，断电不会留下半个文件 |
| 回读校验 | 写完立刻读回来算 sha256，和写入的比对，不一致就报错 |
| 内容去重 | 和 `latest.json` 哈希相同就跳过，不产生无意义的重复快照 |
| 多处落盘 | `backups/`、`~/Documents/DeepSeek 对话备份`、iCloud 云盘（存在才用），任一位置失败不影响其他位置 |
| 保留策略 | 最近 24 小时全留；更早的每天留最后一份；总数上限 120 |
| 本地留底 | 浏览器里同时写 `dschat.v1` 和 `dschat.v1.prev`，主副本损坏时自动回退 |
| 路径校验 | 备份目录不在静态白名单里（404）；按名取快照时严格校验文件名，防目录穿越 |

**防丢的三道自动拦截（v2.7）**

1. **换地址自检**：打开页面时如果本地没有任何对话，会自动问电脑"有备份吗"，有就在首页直接给一个「恢复 N 个会话」按钮——不用你去设置里翻。
2. **本地双副本**：`dschat.v1` 坏了自动回退 `dschat.v1.prev`。
3. **导出提醒**：设置里显示本地占用（MB）、最近一次导出时间（从未导出会标黄）、当前地址。

**按快照恢复**

设置 → 数据 → **选择快照**，会列出电脑上的历史版本（时间 + 大小），点一条就能回到那个时间点。
恢复是合并式的：同 id 的会话取消息更多的版本，本地独有的不删。

**恢复**

设置 → 数据 → **从电脑恢复**。合并策略是"只增不删"：同 id 的会话取消息更多的那份，本地独有的会话保留，所以不会拿旧备份覆盖掉新内容。

## 位置（v3.6）

设置 → 位置。点「获取」，浏览器会弹一次定位授权，然后用免费接口把坐标换成城市名：

```
当前位置  杭州市 拱墅区
更新于 11/21 02:57 · 仅城市级别，不发送精确坐标
```

**只保留城市级别**：坐标取到后立刻四舍五入到 2 位小数（约 1km），用 [BigDataCloud 的逆地理编码](https://www.bigdatacloud.com/) 换成地名，然后**丢弃坐标**，只存城市和区。

**注入方式**：开启「发送给模型」后，每次请求的 system 里会多一行：

```
【用户位置】杭州市 拱墅区
聊到本地话题（天气、出行、附近的东西）时可以直接参考这个位置。
```

配合联网搜索，问「今天杭州天气」它就能真的去查。

**注意**：定位需要 HTTPS（Pages 满足），且必须你手动点「获取」才触发，不会后台偷偷定位。关闭开关后不再发送。

## 内容安全（v3.5）

**固定在 API 默认档**：请求里从不发送 `safety_check`，即默认的 `low`（API 基础内容检查），比 C 端宽松，也不额外增加延迟和审查费用。有测试断言请求体里绝不出现这个字段。

**拒答的两条路径都处理了**：

| 情况 | 服务端表现 | 界面表现 |
| --- | --- | --- |
| 输入被拦 | `400 Content Exists Risk` | 「这条内容被安全策略拦截了，换个说法或换个角度试试」 |
| 输出被拦 | `finish_reason: content_filter` | **保留已生成的部分**，下方标注「后面这段被安全策略截断了」 |

顺手修了一个误导：以前输入被拦会显示「请求格式有误（可能上下文过长）」，方向完全错了。

> 官方文档建议客户端在拒答时清除已显示的文字。这里是**单用户私人应用**，所以反过来处理：半截回答、思考过程都原样保留，只加一条说明。

## 联网搜索（v3.3）

输入框左侧那个地球图标，点亮表示**这条问题允许联网**。是否真的去搜由模型判断——问"冰岛人口"它会搜，问"帮我改这段文字"它不搜。

**原理**

走的是 DeepSeek 的服务端工具，在请求里声明即可，不需要我们调搜索引擎：

```json
"tools": [{ "type": "deepseek_web_search" }, { "type": "deepseek_read_url" }]
```

- 搜索、抓取都在服务端完成，客户端不执行任何工具
- 搜索结果**不计费**（只有模型 token 计费），返回的网页内容会并进上下文
- `deepseek_read_url` 顺带开启：你贴一个链接，它会把网页读进来
- 只有 `deepseek-flash` 支持；用 Pro 时会自动切回 Flash 并提示

**界面上**

- 搜索期间显示「正在联网搜索…」（带呼吸圆点），因为这个协议下工具调用是在最后一个 chunk 一次性下发的，中途没有进度
- 回答下方列出「来源」，带标题和域名，点击用浏览器打开
- 开思考模式时，它会自动变成"深度思考搜索"（搜索 + 打开网页 + 页内查找，最多约 20 步），更慢但更准

**限制**

- 只有 Flash 支持
- 联网回答会明显变慢（几秒到几十秒）
- 你的问题会发给 DeepSeek 的搜索服务

## 语音聊天（v2.4）

点输入框右侧的麦克风，就进入语音模式：**说完停顿 0.7 秒自动发送，回复自动朗读，朗读时你开口就能打断。**

### 前提：必须用 HTTPS

Safari 的语音识别被 WebKit 限制在**安全上下文**里（见 [WebKit 提交](https://github.com/WebKit/WebKit/commit/a3291b3c8e00e25a469c1ef91e03f9637961b5ca)）。`http://192.168.x.x` 不是安全上下文，麦克风根本调不出来。

所以要用 `https://192.168.2.149:8443` 这个地址。项目里自带一个本地 HTTPS 服务（`_src/serve_https.mjs`），首次运行会自动用 openssl 生成自签 CA 和服务器证书，**全部在本机，没有任何对外请求**。

**装证书（推荐，一次搞定）**

1. 手机 Safari 打开 `http://192.168.2.149:8000/ca.crt`，允许下载描述文件
2. 设置 → 通用 → VPN与设备管理 → 安装
3. 设置 → 通用 → 关于本机 → 证书信任设置 → 打开「DeepSeek Local CA」

懒得装也行：打开 `https://192.168.2.149:8443` 时点「高级 → 继续访问」，多数功能可用，但麦克风未必放行。

### 三个实现细节

- **持续监听**：iOS 的 `continuous` 常常被系统中途掐断，所以监听到 `onend` 会自动重启，形成连续收音。
- **打断 + 回声**：朗读时麦克风仍在工作。程序会把识别结果和"正在朗读的文本"做比对，如果像是自己的声音回授就忽略，否则立刻停止朗读。
- **语音模式强制开朗读**：进入语音模式时自动打开「自动朗读」，不用再手动设。

### 限制

- 语音识别由 **系统服务** 完成（可能联网），不是纯离线；断网时识别会失败。
- 中文识别默认不带标点，会出现一整串没有句号的文本。
- 朗读和收音共用音频通道，外放音量太大时回声干扰会更明显，建议用中低音量。

## 语音朗读（v2.3）

两套引擎，在设置 → 语音里切换：

| 音色 | 实现 | 优点 | 代价 |
| --- | --- | --- | --- |
| 系统语音 | iOS `speechSynthesis` | 免费、离线、零延迟 | 音色是手机自带的，偏机械 |
| Stella / Tide | DeepSeek TTS 接口 | 更自然、男女可选 | 联网，按字符计费（中文 1 字算 2 字符，约 ¥0.03/百字） |

**用法**

- **手动**：每条 AI 回复下方有「朗读」按钮，再点一次停止。
- **自动**：设置里开「自动朗读」，回复边生成边读（按句切分入队，不是等全部写完）。

**几个实现细节**

- 朗读前会清洗 Markdown：代码块替换成"这里是一段代码"，去掉 `**`、`#`、链接地址，否则会念出星号和井号。
- 按标点切成句子再送进语音队列，避免 iOS 对超长 utterance 的截断，也让它更早开口。
- 系统语音的语速可调（0.6×–1.5×）；DeepSeek TTS 官方不支持调速，选项会自动隐藏。
- DeepSeek TTS 单次上限 3000 字（接口本身支持 1 万），超出的部分不朗读。

**iOS 的自动播放限制**

Safari 要求语音/音频由用户手势触发。所以第一次开「自动朗读」时，程序会借那次点击做一次"解锁"。
如果自动播放仍被拦，会提示「点一下喇叭重试」，手动点一次即可。

## 主动搭话（实验，v3.0）

侧边栏底部有个「让它先开口」按钮，点一下它会**基于长期记忆和最近的对话**主动说一句。

- 只发一句话，不超过 40 字，最多一个问句
- 明确禁止「在吗」「好久不见」这类空话
- 消息上会带一个「主动」标签，和普通回复区分开
- 用的是 `thinking: false`，快且省
- 每次点击一次 API 调用

效果强依赖记忆质量：记忆里有「豆豆肠胃不舒服」，它才可能问出「豆豆好点了吗」；记忆是空的就只能泛泛而谈。

**为什么不做全自动**：iOS 上页面进后台后定时器会被挂起，固定时间触发并不可靠。要做「准点找你」需要 Web Push（HTTPS + Service Worker + 授权），复杂度高一个量级。先用手动触发验证内容质量，值得再升级。

## 实时时间（v2.9）

模型只知道训练截止日，不知道"今天"。所以每次请求都会在 `system` 最前面注入：

```
【当前时间】2026年11月20日 星期五 05:59（Asia/Shanghai）
说到「今天/昨天/明天」时以这个时间为准，不要凭训练数据猜测。
```

几个要点：

- **每次请求现算**，不是启动时算一次——聊到凌晨、跨天，时间都是准的。
- **时区取手机的**（`Intl.DateTimeFormat().resolvedOptions().timeZone`），不是写死的。
- 明确禁止它"凭训练数据猜日期"，这一句比时间本身更重要。
- 记忆压缩时也会带上当前时间，让"上周""前几天"能换算成具体日期存进往事。
- 首页问候语也带上了日期（「早上好 · 11月20日 周五」）。

代价：每次请求多约 40 token，可忽略。

## 长期记忆（v2.0）

这是"聊得再久也不失忆"的核心：**不靠无限加长上下文，而是定期把长对话压成一段记忆**。

**什么时候压缩**
对话累计到约 15 万 token 时，回复结束后自动触发一次（一次额外的模型调用，几秒钟）。也可以在设置里点「立即整理」。

**压缩成什么**
固定四段，由模型生成（默认「详细」档）：

```
【用户信息】
- 称呼：小林，也叫「林仔」
- 28 岁，后端工程师，做支付系统，主要写 Go
- 在杭州独居，养了一只橘猫叫豆豆
- 讨厌开会和写周报，尤其讨厌「对齐」这个词
- 长期目标：明年三月前跳槽到外企

【重要往事】
- 2026-09 说过和前任分手半年了
- 2026-10 豆豆误食巧克力，半夜送急诊
- 明确说过：不喜欢被叫「宝宝」

【最近发生的事】
- 昨天面试第二家，二面，感觉答得一般
- 上周连续加班五天，最晚到凌晨两点
- 这两天情绪偏低，说「有点提不起劲」

【相处方式】
- 喜欢直接、不绕弯，讨厌客套
- 情绪低时先接住情绪，不要急着给建议
```

**四个段落的分工**

| 段落 | 内容 | 保留规则 |
| --- | --- | --- |
| 用户信息 | 称呼、年龄、职业、住址、家庭、宠物、性格、喜恶、雷区、目标 | 只增不减，没推翻就一直保留 |
| 重要往事 | 约定、承诺、转折点、情绪时刻、反复提起的人和事 | 最多 20 条，单条 80 字 |
| 最近发生的事 | 近期事件、情绪、进行中的计划，带时间 | 最多 24 条，新的覆盖旧的 |
| 相处方式 | 称呼习惯、说话风格、雷区、安慰方式 | 没表达就写「暂无」 |

**三档详细程度**（设置 → 长期记忆）

| 档位 | 重要往事 | 最近发生的事 | 记忆体积 |
| --- | --- | --- | --- |
| 简要 | 5 条 / 30 字 | 8 条 / 30 字 | 约 300 token |
| 标准 | 10 条 / 45 字 | 12 条 / 45 字 | 约 700 token |
| 详细（默认） | 20 条 / 80 字 | 24 条 / 80 字 | 约 1500 token |

**身份连续性（关键）**

记忆会被当作一段"二手资料"读吗？不会——注入时会明确告诉模型这是它的亲身经历：

```
【你和这位用户的过往 · 这是你自己的记忆】
下面这些，是你和这位用户之间真实发生过的事，是你亲身经历的，不是别人转述的资料。
你一直在和同一个人聊天。中间只是因为上下文变长做过一次整理，
你、对方、你们之间的关系都没有变，接着之前的样子继续就行。
因此：不要说自己刚认识对方，不要说「根据记忆」「之前的对话」「上一个窗口」这类话……
```

压缩提示词里也禁止产出「这是 AI 和用户」「之前的助手」这类第三方描述——否则模型读到"某个 AI 和某个用户"的故事，会把自己当成旁观者，开场就说"你好，我是新来的助手"。

**压缩之后**
- 记忆会作为 `system` 消息拼在每次请求最前面。
- 被压缩的原文不再发送，但**仍然留在对话里**，中间会出现一条「长期记忆 · 以上内容已压缩」的分隔线。
- 保留最近 6 条原文，保证上下文衔接自然。

**为什么这样能跳出 1M 限制**
压缩后上下文会回落到几千 token，然后继续增长，到 15 万再压一次。理论上可以无限聊下去，而且**平时比"堆满 800K"更快更便宜**。

**你可以干预**
设置里的「长期记忆」可以手动编辑——记错了就改，不想记得就清空（清空会同时取消分隔线，让旧消息重新参与对话）。

## 上下文满了会怎样

分三层兜底，正常情况下你只会看到第一层：

**第一层 · 记忆范围**（精简 20 轮 / 标准 60 轮 / 长记忆不限）
按「记忆范围」只发送最近的 N 轮；选「长记忆」则不设轮数上限，一直带到 800K token。更早的消息**仍然留在对话里**，只是不发给模型。对话顶部会出现一条
「更早的 6 条消息没有发送给模型」的提示，不会悄悄发生。

**第二层 · token 预算 800K**
1M 是"输入 + 输出"合计，程序预留 200K 给输出，所以输入侧封顶 800K。
超了就从**最早**的消息开始丢弃，直到低于预算；**最新那条永远保留**。
轮数上限改用完之后，这里才会触发。

**第三层 · 服务端拒收**
如果估算失准、真的超了 1M，API 会返回 400 上下文超限。程序会：
丢掉这次失败的回复 → 临时把轮数减半 → 重试一次（**不会改你设置里的值**）→ 还失败就显示错误卡片和「重试」按钮。

几个要点：

- 被丢弃的消息不会从本地删除，只是这一轮不发送。
- 图片每张按 1000 token 计，一次发 4 张就是 4000。
- 进度条按 **800K** 算满，而不是 1M——因为到 800K 就开始丢消息了，按 1M 算永远填不满。
- 想记得久：选「长记忆」；想省钱省等待：选「精简」。

## 关于旧模型名

V3 时代的 `deepseek-chat` / `deepseek-reasoner` 已经不在官方定价页上了。程序在读取旧存档时会自动把它们映射成 `deepseek-flash`，不需要手动改。

思考模式也从"换模型"变成了参数开关：

```json
{ "model": "deepseek-flash", "thinking": { "type": "enabled" }, "reasoning_effort": "high" }
```

开启时 `temperature` 不生效（官方会忽略），所以设置里滑杆会置灰——这是预期行为。

## 几个使用细节

- **换行与发送**：手机上回车是换行，点右侧圆钮发送。外接键盘用 ⌘/Ctrl + Enter。
- **语音输入**：直接用 iOS 键盘自带的听写麦克风，不需要额外权限。
- **看图**：消息里的图片点一下可以全屏查看，再点一下关闭。
- **界面锁定缩放**：viewport 设了 `maximum-scale=1`，输入框字号全部 ≥16px（低于 16 会让 iOS 聚焦时自动放大），另外拦截了 Safari 的双指手势。
- **朗读**：点 AI 回复下方的「朗读」听它念出来，或在设置里开「自动朗读」边生成边读。
- **复制**：走的是 `execCommand` 兜底方案（局域网 HTTP 下 `navigator.clipboard` 不可用），所以能正常用。
- **数据备份**：「设置 → 导出备份」会生成 JSON 存到「文件」App，不含 API Key。

## 限制（都是 iOS 网页端的硬限制）

- **电脑必须开着**：页面由这台 Mac 的 `python3 -m http.server` 提供，Mac 休眠或关掉服务就连不上。
- **只能在同一个 Wi-Fi 下用**：没有公网地址。想在外面也能用，需要把 `index.html` + 两个图标放到任意静态托管（Cloudflare Pages / GitHub Pages 等，均免费且 HTTPS）。
- **不能后台运行**：切到别的 App 后不会继续生成，也不会有推送通知。
- 局域网 HTTP 属于非安全上下文，所以摄像头、定位、剪贴板 API 这类能力不可用（本 App 也没用到）。

## 关于 API

- 接口：`POST https://api.deepseek.com/chat/completions`，OpenAI 兼容格式。
- 已实测该域名对浏览器直连返回 `access-control-allow-origin: <请求来源>`，并允许 `Authorization` 头，
  因此**不需要任何代理服务**，这是选 DeepSeek 的主要原因（OpenAI / Anthropic 的接口从浏览器直连会被 CORS 拦掉）。
- 费用按 DeepSeek 官方价目表计，从你账号余额里扣。
